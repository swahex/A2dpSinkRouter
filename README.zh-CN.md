# A2DP Sink Router

[English](README.md) | 简体中文

在 Windows 上接收手机的蓝牙音频，并播放到你选择的耳机、音箱或 USB DAC。

**绕过 Windows“侦听此设备”，以降低本地音频路由延迟为目标。** 应用使用独立、事件驱动的 WASAPI 路由替代系统内置侦听转发，提供可调缓冲和直接输出选择，无需额外音频路由软件。

**[从 Microsoft Store 获取](https://apps.microsoft.com/detail/9nh7kcmvkcv3)** · **[下载绿色 ZIP](https://github.com/swahex/A2dpSinkRouter/releases/latest)**

商店版 **1.4.3.0** 与绿色版 **0.4.3** 使用相同的源码基线 **0.4.3**。商店负责安装、更新和卸载；GitHub 继续提供自包含和依赖框架两种 ZIP。

## 功能

- 发现已配对手机，支持连接、断开和重新连接，并按手机记住路由选择。
- 自动刷新音频端点的可用状态；可以在播放开始前请求路由，也可以取消等待中的请求。
- 通过事件驱动 WASAPI 将采集音频转发到指定输出，支持共享模式和可选独占模式。
- 有界缓冲、重采样、设备时钟漂移补偿、路由音量、静音和诊断统计。
- 首次启动选择语言，支持中英文即时切换、保存亮暗主题和托盘控制。
- 简洁的分区界面、自适应分栏、固定路由操作区和独立活动日志。

## 为什么绕过“侦听此设备”？

Windows 可以通过“侦听此设备”将 A2DP 输入转发到播放设备，但其侦听缓冲由系统管理，“侦听”选项卡不提供预缓冲或音频引擎周期控制。厂商支持渠道和用户反馈中，明显的侦听延迟是一个反复出现的问题。

**A2DP Sink Router 用专门为低延迟设计的路由替代这段转发。** Windows 接收并解码蓝牙音频后，应用通过事件驱动 WASAPI 采集，再经有界队列发送到所选输出。它请求设备支持的最小共享引擎周期，补偿输入与输出的时钟差，并清理过多积压，避免旧音频持续堆积。你可以调节预缓冲，在响应速度和流畅播放之间取得平衡，也可以在兼容设备上使用独占输出。

| | Windows“侦听此设备” | A2DP Sink Router |
| --- | --- | --- |
| 本地延迟调节 | 系统管理侦听；侦听页不提供预缓冲或引擎周期控制 | 5–100 ms 可调预缓冲，默认 12 ms；请求最小支持的共享引擎周期 |
| 缓冲管理 | 侦听页不显示队列行为 | 有界队列、时钟漂移补偿及过量积压清理 |
| 播放设备 | 在 Windows 录音设备属性中配置 | 在应用中指定耳机、音箱或 DAC，不改变系统默认输出；按手机记忆路由 |
| 路由控制 | 在 Windows 声音属性中启用或关闭侦听 | 在同一窗口中开始、停止、调节音量、静音及取消等待中的路由 |
| 故障排查 | 侦听页不提供队列或欠载统计 | 队列时间、设备周期、帧数、欠载和丢帧统计 |


## 系统要求

- Windows 10 2004（build 19041）或更新版本，x64。
- 电脑需具备可用的蓝牙功能，并已在 Windows 蓝牙设置中与手机配对。手机与 Windows 蓝牙驱动需支持 A2DP 接收。
- 仅依赖框架的 ZIP 需要 **.NET 10 Desktop Runtime x64**；商店版和自包含 ZIP 已包含运行时。
- 使用前先在 Windows 蓝牙设置中与手机配对。

## 使用方法

1. 从 Microsoft Store 安装，或完整解压绿色 ZIP 并保留所有文件。切换版本前先退出正在运行的副本。
2. 首次启动选择简体中文或英文；已有设置会跳过此对话框。
3. 选择手机，点击“连接 / 重连”。
4. 选择对应的 A2DP 输入和目标输出，点击“开始路由”，再在手机播放音频。
5. 输入尚未就绪时，路由会自动等待；点击“取消等待”可移除该请求。

通过“语言”切换中英文，通过“偏好 → 外观”选择亮暗主题，通过“窗口”菜单收起到托盘或退出。双击托盘图标可恢复窗口。默认关闭窗口会收起到托盘，这一偏好可以关闭。停止路由会保留蓝牙连接，退出程序会释放连接。

默认预缓冲目标为 12 ms，可在 5–100 ms 间调整。更改缓冲或独占模式设置前先停止路由。独占模式会占用所选输出设备。

较小缓冲对音频包到达抖动和时钟差更敏感，默认值不能保证在每个设备上都稳定播放。若出现断音或欠载持续增加，请停止路由，增大预缓冲（例如先试 40 ms），再重新开始。较大缓冲也会增加本地等待时间。

电平、帧数、队列时间和设备周期均为诊断值，不是端到端蓝牙延迟测量。

绿色 ZIP 版的设置和日志保存在 `%LOCALAPPDATA%\A2dpSinkRouter\`。移除绿色版时，从托盘退出并删除解压目录；如需清除设置和日志，再删除该数据目录。

商店版将设置和日志保存在包专属的 `LocalCache\A2dpSinkRouter` 目录。更新通常保留这些数据；通过 Windows 普通卸载或重置应用会移除包管理的数据。更新前请从托盘退出。“偏好 → 打开数据目录”可打开当前渠道的数据位置。蓝牙配对、单独安装的 .NET 运行时以及另行导出的副本仍分别管理。

绿色版与商店版的设置独立，不自动迁移；同一 Windows 会话中共用单实例限制，启动另一个版本前先退出当前版本。

商店的“使用全部系统资源”权限对应以普通用户权限运行的 full-trust 桌面程序；“使用麦克风”对应所选音频输入的采集，包括启用后可选的其他录音设备。音频在本机处理，应用不保存录音或上传音频。

本地音频处理、设置和日志的说明见[隐私政策](PRIVACY.md)。

启动偏好只在启动时连接一次上次选择的手机，不会在后台无限重试或重新启动音频路由。手动重连会释放旧手机会话。连接过程中，“断开”会变为“取消连接”。停止路由会保留蓝牙连接；断开连接也会取消等待中的路由。

## 构建

在 Windows 上安装 .NET 10 SDK，然后从仓库根目录运行。`global.json` 选择稳定版 .NET 10 SDK：

```powershell
.\tools\Build.ps1
# 输出：artifacts/win-x64/A2dpSinkRouter.exe

# 可选：包含运行时（初次还原会下载运行时包）
.\tools\Build.ps1 -SelfContained

# 可选：合成算法检查，不访问声卡或蓝牙
.\tools\Build.ps1 -CheckAudioCore

# 构建、检查并生成两种部署方式的 ZIP
.\tools\Package.ps1
```

构建应用不需要 Node.js。图标资源已经包含在源码中。如需重新生成：

```powershell
npm install --prefix tools/icon @napi-rs/canvas
node tools/Draw-Icon.cjs
```

没有安装 .NET 的电脑请选择自包含 ZIP；已安装 .NET 10 Desktop Runtime x64 时，可选择较小的依赖框架 ZIP。两种程序包都必须完整解压。自包含版本包含自己的运行时，因此运行时安全修复需要重建并替换应用程序包。

普通 `main` 推送和面向 `main` 的拉取请求会运行 Windows 构建及合成检查。与项目版本匹配的标签（如 `v0.4.2`）会执行发行检查，打包两种部署方式，并使用对应版本的更新记录创建 GitHub Release 草稿。发布前请审核说明和附件，也可以手动运行 CI。

现有 Windows API 基线仍为 build 19041。这是应用兼容性目标，不代表微软仍支持该版本之后的每一个 Windows 版本。受支持的系统请参阅 [.NET Windows 支持矩阵](https://learn.microsoft.com/dotnet/core/install/windows)，并在计划使用的 Windows 版本上测试程序包。

## 架构

Windows `AudioPlaybackConnection` 负责管理蓝牙接收。数据路径直接调用 Core Audio，采集所选输入，经有界缓冲、重采样和设备时钟补偿，路由到所选 WASAPI 输出。

维护者已使用多台手机、电脑和耳机验证正常使用，测试使用电脑内置蓝牙；未验证外接 USB 蓝牙棒。自动回归另覆盖合成音频缓冲、连接生命周期、侦听设置检测及无需设备的界面预览。
